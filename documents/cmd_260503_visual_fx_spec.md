# パラメータ関係
## パラメータ分類ルール

本プロジェクトでは数値を以下の2種類に分類すること。

---

### ① TUNING（バランス調整値）

ゲーム体験に直接影響する値。

例：
- 水位上昇速度
- 危機までの時間（秒）
- 波の強さ
- 振動強度
- 雷発生頻度

#### ルール
- すべてconstantsとして定義する
- 一箇所に集約する
- プレイテストで頻繁に変更する前提とする

---

### ② CONFIG（設定値）

ゲーム仕様や表示に関する値。

例：
- UIの位置
- 色コード
- フォントサイズ
- 表示文言

#### ルール
- constantsとして定義する
- 変更頻度は低い

---

### 優先度

TUNINGを最優先で整理すること。
CONFIGは過剰に分離しなくてよい。

---

### 意図

- 調整作業を高速化する
- ゲームの体感を改善しやすくする

## 定数（constants）管理ルール

### 方針
本仕様に含まれる数値は、すべて定数として定義すること。
コード中へのベタ書きは禁止。

---

### 定義場所

- ファイル分割は不要（現時点では単一ファイルでOK）
- ただし、ファイル先頭に「定数セクション」を作成すること

例：

```js
// =========================
// CONSTANTS
// =========================

セクション分割
以下のカテゴリごとに整理すること：
// WATER（波・色）
// DANGER（危機判定・距離・時間）
// UI（カウントダウン・色・スケール）
// RADAR（線・透明度・枠）
// EFFECT（雷・振動・演出）
// RAIN（雨量）

命名ルール
すべて大文字＋スネークケース
単位・意味が分かる名前にする
例：
BASE_WAVE_AMPLITUDE
DANGER_COUNTDOWN_SECONDS
RADAR_LINE_WIDTH
SHAKE_INTENSITY_STRONG

禁止事項
数値の直書き（マジックナンバー）
同じ値の重複定義

意図
プレイテスト時の調整を容易にする
数値変更の影響範囲を限定する
可読性・保守性を向上させる
